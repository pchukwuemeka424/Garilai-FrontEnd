1. Executive summary

This review assesses Garil AI’s codebase against SOC 2 Trust Services Criteria using concrete file evidence. It is not a formal SOC 2 Type I or Type II report. Formal attestation requires an independent CPA firm and organizational evidence (policies, vendor DPAs, HR/access, incident response runbooks) beyond application code.

Governance product surfaces (append-only audit log, retention UI, policy gates, university-scoped RBAC) are a useful foundation. The platform is not SOC 2 ready until critical logical-access failures and operational control gaps are closed.

5. Remediation roadmap

Week 1 — Stop the bleed

  1. Auth-gate or remove /api/users and open dashboard routes
  2. Disable default admin in prod (DEFAULT_ADMIN_ENABLED=false); rotate secrets
  3. Set explicit CORS_ORIGIN; enable Fastify logger
  4. Add rate limits on login / forgot-password / AI

Weeks 2–4 — Control foundation

  1. httpOnly cookie sessions or token version + revoke
  2. CI: lint, typecheck, dependency audit before deploy
  3. Sentry (or equiv) + auth audit events
  4. Publish real Terms/Privacy/AUP; server-enforce policy version
  5. Helmet/security headers; sanitize portal HTML

Weeks 5–10 — SOC 2 readiness

  1. Cascade erase + retention job; user export/delete
  2. Subprocessor inventory + OpenRouter DPA / retention settings
  3. Scheduled backups + tested restore; Mongo-aware health
  4. MFA for admins; password policy; email verify
  5. IR runbook, on-call alerts, vendor risk register (org)

7. Bottom line

Governance product surfaces (audit log, retention UI, policy gates, university RBAC) are a useful foundation, but the platform is not SOC 2 ready. Prioritize F1–F2 immediately — they are exploitable logical access failures — then build observability, CI, privacy enforcement, and organizational evidence for an auditor engagement.
